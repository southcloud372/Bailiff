## 一、项目简介

**本地生活商户服务平台**是一个面向本地生活场景的服务平台，核心围绕**高并发交易**（限时抢购、订单交易）与 **AI 智能客服**两大业务线，构建覆盖「高并发防护 → 原子扣减 → 异步削峰 → 跨系统最终一致 → 可观测」的完整交易体系，并将大模型能力以**服务治理**的方式工程化落地。

| 维度 | 说明 |
|------|------|
| **项目类型** | Spring Boot 后端（单体架构 + Redis/RabbitMQ/PgVector 外部组件） |
| **核心场景** | 限时抢购、订单交易、AI 智能客服 |
| **后端框架** | Spring Boot 3.x、MyBatis-Plus |
| **AI 框架** | LangChain4j（Agent 编排、Function Calling） |
| **开发周期** | 2025.06 - 2026.01 |
| **角色** | Java 后端开发（独立负责交易链路与 AI 工程化） |

## 三、系统架构（交易链路为核心）

```
                        ┌──────────────────────────────┐
                        │   限时抢购入口（秒杀接口）      │
                        │   /voucher-order/seckill/{id} │
                        └──────────────┬───────────────┘
                                       │ ① 滑动窗口限流 + traceId 注入
                                       ▼
                        ┌──────────────────────────────┐
                        │   Redis Lua 原子预扣          │
                        │   EXISTS→时间窗口→库存→限购→扣减│
                        │   （单次 EVAL，消除竞态）       │
                        └──────────────┬───────────────┘
                                       │ ② 写本地消息表（PENDING）
                                       ▼
                        ┌──────────────────────────────┐
                        │   RabbitMQ 异步投递（削峰）    │
                        │   Direct Exchange + 发布确认  │
                        └──────────────┬───────────────┘
                                       │ ③ 消费者落库
                                       ▼
                        ┌──────────────────────────────┐
                        │   MySQL 落库（@Transactional）│
                        │   乐观锁 CAS + 唯一索引幂等     │
                        └──────────────┬───────────────┘
                                       │ ④ 定时对账 / 超时关单兜底
                                       ▼
                        ┌──────────────────────────────┐
                        │   本地消息表对账 + 死信补偿     │
                        │   订单超时关单 + 库存回补       │
                        └──────────────────────────────┘
```

**贯穿全链路**：`TraceIdFilter` 在请求最外层生成 traceId 并注入 MDC，一次下单的「限流 → 预扣 → 投递 → 落库 → 对账」日志可用同一 ID 串联；`TraceRecorder` 对 AI 链路做成本归因。

## 四、核心模块概览（按简历 5 条顺序）

| # | 模块 | 一句话概括 | 核心价值 |
|---|------|-----------|----------|
| 1 | **跨系统数据一致性** | 针对「Redis 预扣 → MQ 投递 → 消费者落库」三阶段跨系统操作，引入本地消息表 + 定时对账 + 失败补偿，将跨系统双写收敛为最终一致；对账先反查订单再补偿，配合超时关单回补 | 异常场景下库存与订单守恒 |
| 2 | **高并发交易的库存一致性** | Lua 脚本将库存校验、扣减、限购约束收敛进单次原子执行；DB 层乐观锁 CAS + 唯一索引兜底，三级防线防库存透支与重复写入 | 从机制上避免超卖/重复下单 |
| 3 | **异步解耦与消息可靠消费** | RabbitMQ 削峰 + Direct Exchange + 手动确认 + 死信 + 失败重试；修复重试计数失效导致的毒消息循环重投 | 压测 350ms→130ms |
| 4 | **全链路追踪与可观测性** | 请求级 traceId 贯穿 Redis/MQ/DB/模型，成本归因 + 容量评估，Prometheus + Micrometer 监控 | 可观测、可定位、可复盘 |
| 5 | **AI 能力工程化与治理** | 「路由 + 专业子智能体」编排 + LLM-as-Judge 评测闭环 + 多模型路由/降级/分级限流/语义缓存 | 准确率 72%→89%，成本降 50% |

> **说明**：区块链可信存证（ChainNotary）、MCP 工具链、三层记忆、Advanced RAG 等为**项目内已实现但未写入当前简历**的能力，代码仍在（详见 `02` 相关章节），面试时作为"超出简历"的加分项按需展开，不作为简历主线。

## 六、关键指标

> 以下数字均来自简历口径，面试需按 `终极自检报告.md` 第 8 节"诚信披露"的对应口径陈述。

| 指标 | 数值 | 对应模块 |
|------|------|----------|
| 接口平均响应时间 | 350ms → **130ms**（降幅 63%，50 并发 JMeter） | 异步削峰 |
| 工具调用准确率 | 72% → **89%** | Agent 编排 + LLM-as-Judge 评测 |
| AI 调用成本 | **降低 50%** | 多模型路由 + 分级限流 + 语义缓存 |
| 结构防线 | **三级**（原子预扣 / 乐观锁 / 唯一索引） | 库存一致性 |
| 跨系统链路 | **三阶段**（Redis → MQ → MySQL） | 数据一致性 |
| 追踪覆盖 | **四类组件**（Redis/MQ/DB/模型） | 可观测性 |
