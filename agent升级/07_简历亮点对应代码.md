## 一、项目五条工作内容 ↔ 代码映射

> 顺序与最新简历严格一致：① 跨系统数据一致性 → ② 高并发库存一致性 → ③ 异步解耦与消息可靠消费 → ④ 全链路追踪与可观测性 → ⑤ AI 能力工程化与治理。

### 1.1 工作内容一：跨系统数据一致性（本地消息表 + 对账 + 补偿）

| 简历表述 | 真实代码 |
|----------|----------|
| 本地消息表（事务性发件箱） | `entity/SeckillMessage.java`（PENDING/CONFIRMED/COMPENSATED 三态）· `mapper/SeckillMessageMapper.java` · `service/ISeckillMessageService.java` · `service/impl/SeckillMessageServiceImpl.java`（savePending/markConfirmed/markCompensated 条件更新幂等） |
| 定时对账 | `task/SeckillMessageReconcileTask.java`（`@Scheduled` 扫描 PENDING，先反查订单再决定补偿，指数退避重投） |
| 对账判定顺序（先反查订单避免误回滚） | `SeckillMessageReconcileTask.handle()`：`voucherOrderService.getById(orderId) != null → markConfirmed`，未落库才重投/补偿 |
| 订单超时自动关单 | `listener/OrderTimeoutListener.java`（延时队列消费）· `service/impl/VoucherOrderServiceImpl.closeOrderIfUnpaid()`（`WHERE status=1` 条件更新 + 双端回补） |
| 库存回补（仅活动未结束才回补） | `resources/restore_stock.lua`（EXISTS 判断 + INCRBY）· `VoucherOrderServiceImpl` RESTORE_STOCK_SCRIPT |
| 消息表 DDL | `resources/db/seckill_message.sql`（`idx_status_next_retry` 索引） |

### 1.2 工作内容二：高并发交易的库存一致性（Lua + CAS + 幂等）

| 简历表述 | 真实代码 |
|----------|----------|
| Lua 原子预扣（消除读-判-写竞态） | `resources/seckill.lua`（EXISTS→时间窗口→库存→限购→扣减 单次 EVAL；KEYS 显式声明，Bitmap 限购）· `service/impl/VoucherOrderServiceImpl.doSeckillVoucher()` |
| 时间窗口下沉（同步链路零 DB 查询） | `seckill.lua`（HGET activity:begin/end 判断）· `utils/SeckillActivityCacheWarmer.java`（预热 activity Hash + 启动补偿预热） |
| 单人限购（Bitmap 替代 Set 防大 key） | `seckill.lua`（GETBIT/SETBIT）· `utils/RedisConstants.SECKILL_ORDER_KEY` |
| 乐观锁 CAS 兜底 | `VoucherOrderServiceImpl.createVoucherOrder()`：`update().setSql("stock=stock-1").eq("voucher_id").gt("stock",0)` |
| 唯一索引幂等 | `resources/db/hmdp.sql` `uk_user_voucher(user_id,voucher_id)` · `createVoucherOrder()` 捕获 `DuplicateKeyException` |
| 三级防线 | ① Lua 原子预扣 ② 乐观锁 CAS ③ 唯一索引（见 `02` 秒杀章节"三层防线总结"） |

### 1.3 工作内容三：异步解耦与消息可靠消费（MQ + 毒消息修复）

| 简历表述 | 真实代码 |
|----------|----------|
| RabbitMQ 异步削峰 | `config/RabbitMQConfig.java`（ORDER_EXCHANGE/ORDER_QUEUE/DLX + ORDER_DELAY_QUEUE 延时队列）· `VoucherOrderServiceImpl.doSeckillVoucher()` 投递 |
| Direct Exchange 精准路由 | `RabbitMQConfig.orderExchange()/orderBinding()` |
| 手动确认 / 失败重试 | `listener/OrderMessageListener.java`（`basicAck` / `basicNack`） |
| 毒消息修复（Redis 计数替代 x-death） | `OrderMessageListener.java`：`incrementRetryCounter()`（Redis INCR + TTL）替代 `getRetryCount()`（原读 x-death，恒为 0） |
| 异常分流 | `OrderMessageListener`：`SeckillRejectException`（业务拒绝）→ 直转死信；其余 → 有限重试；`exception/SeckillRejectException.java` |
| 死信补偿 | `listener/DlxOrderListener.java`（反查订单是否落库 → 回补 Redis 库存 + 清 Bitmap 位 + 收敛消息表状态） |
| 发布确认 / Returns 回调 | `config/RabbitMQPublisherCallback.java`（confirm/returns 失败落 Redis LIST） |
| JMeter 压测（350ms→130ms） | `../jmeter/seckill-load-test.jmx`（50 线程）· `../jmeter/压测说明.md` |

### 1.4 工作内容四：全链路追踪与可观测性
