# 本地生活商户服务平台 — 安装与启动指南

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 17+ | Spring Boot 3.x 要求 |
| Maven | 3.8+ | 构建工具 |
| MySQL | 8.0+ | 业务数据库 |
| Redis | 6.0+ | 缓存/记忆/签到 |
| PostgreSQL | 15+ | RAG 向量存储 |
| RabbitMQ | 3.8+ | 消息队列（秒杀用） |
| Docker | 20+ | 可选，用于快速启动 PgVector |

---

## 二、快速启动（3步）

### 第1步：启动 PostgreSQL + pgvector

```bash
# 使用 Docker 启动 pgvector（推荐）
docker run -d \
  --name pgvector \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=123456 \
  pgvector/pgvector:pg16

# 创建 RAG 数据库
docker exec -it pgvector psql -U postgres -c "CREATE DATABASE dianping_rag;"
```

### 第2步：初始化 MySQL 数据库

```bash
# 导入项目自带的数据库脚本（业务表）
mysql -u root -p123456 < lewan/src/main/resources/db/hmdp.sql
# 导入本地消息表（跨系统数据一致性用，必须）
mysql -u root -p123456 < lewan/src/main/resources/db/seckill_message.sql
```

### 第3步：启动应用

```bash
cd lewan
mvn spring-boot:run
```

启动后访问：
- 前端页面：`http://localhost:8081/hmdp/ai.html`
- 健康检查：`http://localhost:8081/ai/health`
- 系统状态：`http://localhost:8081/ai/status`

### 3.7 数据库说明

- **秒杀一人一单**：`tb_voucher_order` 已添加 `UNIQUE KEY uk_user_voucher(user_id, voucher_id)`，配合 `@Transactional` + 乐观锁（`stock > 0`）实现数据库层幂等与防超卖（见 `resources/db/hmdp.sql`）。
- **本地消息表**：`tb_seckill_message`（`resources/db/seckill_message.sql`）用于跨系统数据一致性——Redis 预扣成功后先落一条 PENDING 凭据，定时对账任务（`SeckillMessageReconcileTask`）据此重投或补偿，保证「Redis 预扣 → MQ 投递 → 消费者落库」最终一致。**必须导入，否则下单链路报表不存在。**
- **延时关单队列**：`RabbitMQConfig` 中声明 `seckill.order.delay.queue`（TTL 15min）+ `seckill.order.timeout.queue`，由 Spring AMQP 自动 declare，无需手动建。
- **存量存证/评测数据**：ChainNotary 存证（已移出简历主线，代码保留）、AgentEval 报告、AgentTrace 均持久化于 Redis（Key 前缀 `chain:notary:*`、`ai:eval:*`、`agent:trace:*`），无需额外建表；RAG 向量数据在 PgVector。

### 3.8 编译与启动

```bash

# 启动
mvn spring-boot:run

# 或者打包后运行
mvn clean package -DskipTests
```

## 四、启动后初始化

### 4.1 数据摄入（必须）

首次启动后，需要调用数据摄入接口将业务数据向量化：

```bash
# 全量摄入（店铺+评价）
curl -X POST http://localhost:8081/ai/ingest

# 返回：全量摄入完成: 摄入完成: 店铺=X, 评价=Y
```

### 4.2 增量更新

后续数据变更后，调用增量摄入：

```bash
curl -X POST http://localhost:8081/ai/ingest/incremental
```

### 4.3 验证系统状态

```bash
# 健康检查
curl http://localhost:8081/ai/health

# 系统状态
curl http://localhost:8081/ai/status

# AI 指标
curl http://localhost:8081/ai/metrics
```

### 4.4 工程化四件套验证（可选）

```bash
# 1) 语义缓存命中统计（多问几次"推荐附近的火锅"后再看命中率）
curl http://localhost:8081/ai/cache/stats

# 2) AgentEval 评测（LLM-as-Judge，需 LLM key 可用）
curl -X POST http://localhost:8081/ai/eval/intent
curl -X POST http://localhost:8081/ai/eval/quality
curl http://localhost:8081/ai/eval/latest

# 3) ChainNotary 存证与校验（验证防篡改）
# 3.1 手动存证一条记录 → 返回 recordId
curl -X POST http://localhost:8081/ai/notary/record \
  -H "Content-Type: application/json" \
  -d '{"eventType":"MANUAL_TEST","content":"{\"hello\":\"world\"}"}'
# 3.2 按 recordId 校验（valid=true 说明未被篡改）
curl http://localhost:8081/ai/notary/verify/{recordId}
# 3.3 强制封块（让缓冲中的记录立刻上链）
curl -X POST http://localhost:8081/ai/notary/flush
# 3.4 全链完整性校验
curl http://localhost:8081/ai/notary/chain/verify
```

> **离线验证**：ChainNotary 的密码学核心（Merkle 树、哈希链、签名）不依赖外部服务即可单测——仓库自带 `NotarySelfTest` 思路可复用：直接用 `MerkleTree.of(...)` / `MerkleTree.verify(...)` 验证根/证明/篡改检测。

### 4.5 秒杀压测（JMeter，支撑简历 350ms→130ms）

```bash
# 压测计划与完整说明在项目 jmeter/ 目录：
#   jmeter/seckill-load-test.jmx   —— JMeter 测试计划
#   jmeter/压测说明.md              —— 前置准备/操作步骤/结果解读/同步vs异步对照复现
```

按 `压测说明.md` 三步走：①创建秒杀券 → ②生成 N 个登录 token 写入 `tokens.csv` → ③运行 JMeter 读聚合报告。

## 五、前端访问

### 5.1 配置 Nginx（可选）

如果需要通过 Nginx 反向代理：

```nginx
server {
    listen 80;
    server_name localhost;

    # 前端静态文件
    location /hmdp/ {
        alias /path/to/nginx-1.18.0/html/hmdp/;
    }

    # API 代理
    location /ai/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # SSE 代理（需要特殊配置）
    location /ai/chat/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
        proxy_buffering off;
        proxy_cache off;
    }
}
```

### 5.2 直接访问

启动后直接访问：
```
http://localhost:8081/hmdp/ai.html
```

## 七、常见问题

### Q1: pgvector 连接失败
```
错误：Connection refused to localhost:5432
```
**解决**：检查 Docker 是否启动，或 PostgreSQL 服务是否运行。

### Q2: embedding 模型调用失败
```
错误：401 Unauthorized
```
**解决**：检查 `application.yaml` 中的 `api-key` 是否正确。

### Q3: 数据摄入后搜索无结果
**解决**：确保调用了 `POST /ai/ingest` 接口，并等待摄入完成。

### Q4: SSE 流式响应不生效
**解决**：检查 Nginx 配置中是否关闭了 `proxy_buffering`。

### Q5: 内存不足
```
错误：java.lang.OutOfMemoryError
```
**解决**：增加 JVM 内存：
```bash
mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Xmx2g"
```
