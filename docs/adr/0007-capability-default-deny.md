# ADR 0007：能力默认拒绝（离线模型 / 只读模式 / 出网白名单）

- 状态：已采纳
- 日期：2026-11-10
- 相关：`gateway/config.py`、`gateway/wiring.py`、`core/mock.py`、`tools/web.py`

## 背景

开源 Agent 项目普遍面临一个矛盾：

1. **体验**上，clone 下来必须能立刻跑，否则没人会读你的代码（要填 key、要起数据库的项目，
   绝大多数人走到第一步就走了）；
2. **安全**上，一个「能任意出网、能任意写文件、缺 key 也能跑」的服务，一旦被部署到公网
   就是现成的跳板机或免费网盘。

这两个需求在实现上高度冲突。天真的做法是「默认全开，靠配置关掉」，但那等于**默认不安全**——
绝大多数部署不会去改默认值。

## 决策

采用「**能力默认拒绝**」（capability default-deny）模型，三条规则同构：

| 能力 | 默认 | 开启方式 | 关闭时的形态 |
|---|---|---|---|
| 真实模型 | 缺 key 时降级离线模型 | 配置 `DEEPSEEK_API_KEY` | 仍可跑通全链路，但 `/readyz` 标 degraded，**prod 下判不就绪** |
| 文件写入 | 开启 | `AGENT_READ_ONLY=true` 关闭 | **工具不注册**（不是注册后拒绝） |
| 出网抓取 | **关闭** | `AGENT_HTTP_ALLOWED_HOSTS` 配置白名单 | **工具不注册** |

三条共用一个判据：**关闭 = 能力不存在，而不是能力存在但会被拒**。

## 理由

### 为什么「不注册」优于「注册后拒绝」

1. **模型看不见就不会尝试**。注册后拒绝会导致 `try → denied → 换参数再 try` 的循环：
   浪费 token、污染上下文、用户体验是「它一直在试但什么也做不了」。
2. **没有可绕过的分支**。权限检查是代码，代码可能有 bug；不存在的函数没有 bug。
   `/v1/auth/dev-token` 同理——生产环境这条路由压根不注册，而不是注册后判断 `env`。
3. **工具清单即能力清单**。`/v1/tools` 的返回就是 Agent 的全部可能动作，审计时一眼看得完。

### 为什么离线模型要留在仓库里

它是唯一能让「零依赖可跑」和「CI 不需要密钥」同时成立的方案。
但必须防止它悄悄上生产，所以：

- `AGENT_LLM_BACKEND=auto`（默认）：有 key 用真模型，无 key 降级并**打印 warning**；
- `AGENT_LLM_BACKEND=deepseek`：缺 key 直接抛错，绝不静默降级；
- `/readyz` 的 `llm` 探针在 `env != dev` 时是 **critical**——带假模型上线会被负载均衡挡住。

## 后果

**收益**

- `git clone` 到看见界面 < 1 分钟，无需任何账号；
- 公网演示可以安全开放（`AGENT_READ_ONLY=true` + 离线模型 + 无出网）；
- 安全默认值意味着「配置写错」的失败方向是**功能不可用**，而不是**数据泄露**。

**代价**

- 三个能力各自多一个配置项，配置矩阵变长（已在 `docs/operations.md` 列表化）；
- 「工具不存在」的报错对用户不如「无权限」直观，需要在提示里说明如何开启；
- 离线模型的响应是确定的模板文本，读起来像「坏掉了」，需要在回复里自报身份
  （已在 `core/mock.py` 的回复文案里做）。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 默认全开 + 文档提醒 | 默认值才是真实行为，文档没人读 |
| 用一个 `demo` 环境变量统管 | 三个能力粒度不同（有人要出网但不要写入），合并后无法单独控制 |
| 出网用「黑名单拦内网」 | 黑名单永远漏（IPv6、十进制 IP、DNS rebinding）；白名单才可枚举 |
| 离线模型只在测试里存在 | 那就回到「clone 下来必须有 key」，开源转化率归零 |
