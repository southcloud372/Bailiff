# 19 · 16 周学习计划：从「Python 粗学过」到能讲清一个生产级 Agent 项目

这篇解决一个具体问题：你知道要学 Agent，但不知道先学什么、学到什么程度算够、16 周怎么排。
读完你有一张按周执行的表：每周的目标、要读的章节、要写的代码、可验证的产出，以及面试时能
讲的一句话。

适用对象：大四、Python 只写过课程作业、没系统学过 LangChain、目标 2027 届校招 AI/Agent 开发岗；前提是每周至少投入 10 小时，其中至少 6 小时写代码。

---

## 1. 时间预算：每周 10 小时是底线，不是目标

10 小时不是「抽空看看」，而是一个需要提前占位的固定预算。两种可执行的排法：

| 排法 | 工作日 | 周末 | 合计 |
|---|---|---|---|
| A | 2 个晚上 × 2h | 周六 6h | 10h |
| B | 3 个晚上 × 1.5h | 周日 5.5h | 10h |

时间分配：60% 写代码（6h）、25% 读文档/源码（2.5h）、15% 写输出/复盘（1.5h）。

三条现实约束：不用看视频代替写代码；考试周/加班周设 4 小时维持线；每周必须有可运行产出，跑不通不算完成。

16 周 × 10 小时 = 160 小时。这个投入不足以「精通」，但足够把一个项目讲到能追问细节。

## 3. 第一阶段（1-6 周）：打基础

每周的「验收」就是本周验收标准：不是「看完了」，而是能当场运行、能指出代码位置、能讲出取舍。

### 第 1 周：Python 工程化，不再写「脚本」

- **目标**：会用 uv、类型注解、Pydantic、pytest 组织一个小项目。
- **读**：`docs/learning/10-Python与工程基础.md` §1-§4、§7-§8；
  `docs/stack-verification-2026-11.md` §2.12。
- **写**：一个 CLI 聊天程序：配置从环境变量读、消息用 Pydantic 建模、3 个 pytest 用例。
- **验收**：`uv run pytest -q` 全绿；`uv run python chat.py "你好"` 能打印回复；
  `mypy` 无报错。
- **一句话**：我用 uv 锁文件、Pydantic 边界校验和 pytest 把「脚本」变成了可复现的工程。

### 第 2 周：LLM API 的基本功

- **目标**：理解 token、上下文、temperature、流式、function calling、计费。
- **读**：`docs/learning/13-LangChain与LangGraph.md` §1.1-§1.4；
  `docs/stack-verification-2026-11.md` §2.13（DeepSeek 价格与能力）。
- **写**：一个 token/成本估算器：输入消息，打印 prompt/completion token、费用、
  缓存命中与未命中的差价；再写一个流式输出版本。
- **验收**：同一段 2000 字中文，估算值与 API 返回的 usage 误差可解释；能说清
  「缓存命中价约为未命中价的 1/50」对成本意味着什么。
- **一句话**：我能算清一次对话的成本，而不是只看月底账单。

### 第 3 周：Prompt 与结构化输出

- **目标**：会写带约束的 prompt，能用 function calling 拿结构化结果。
- **读**：`docs/learning/13-LangChain与LangGraph.md` §2-§3；
  `docs/stack-verification-2026-11.md` §2.13（DeepSeek 只有 json_object）。
- **写**：一个「工单分类器」：输入一句话，输出 `{intent, tool_name, args}`；
  写 15 条 golden（问题 + 期望意图），跑一遍统计准确率。
- **验收**：15 条里至少 12 条正确；错误能归因到「意图歧义/参数缺失/prompt 不清」。
- **一句话**：我把 prompt 改动变成了有 golden 集的回归，而不是改完凭感觉。

### 第 4 周：手写 ReAct 循环（不用框架）

- **目标**：理解 Agent 循环的本质：模型出 tool_call → 执行 → 观察 → 再问模型。
- **读**：`docs/learning/13-LangChain与LangGraph.md` §3.2、§4；
  `docs/adr/0001-langgraph-and-mcp-gateway.md`。
- **写**：150-250 行的 `mini_agent.py`：3 个工具（查时间、读文件、算数）、
  `max_steps=6`、工具参数 Pydantic 校验、每步打印 trace。
- **验收**：能完成「先读文件再总结」的两步任务；超过 6 步能主动停止并报错；
  工具参数缺失不会把异常直接抛给用户。
- **一句话**：我不依赖框架手写过 ReAct 循环，知道死循环、工具幻觉和参数校验该在哪断。

### 第 5 周：RAG 基础

- **目标**：理解切块、embedding、向量检索、HNSW、recall@k。
- **读**：`docs/stack-verification-2026-11.md` §2.9；`agent_platform/knowledge/` 的
  `chunking.py`、`store.py`、`rag.py`。
- **写**：一个 ingest + search CLI：把 10 篇 Markdown 切块写入 pgvector，
  用 20 条「问题 → 应命中片段」测 recall@5。
- **验收**：打印 recall@5 基线；把 `top_k` 从 2 调到 8，能解释召回与噪声的取舍；
  能说清 HNSW 的 `m`、`ef_construction`、`ef_search` 各影响什么。
- **一句话**：我用 recall@k 调过 RAG，而不是拍脑袋定 top_k=4。

### 第 6 周：记忆与上下文

- **目标**：分清工作记忆、会话状态、长期记忆，并各写一个最小实现。
- **读**：`docs/learning/16-记忆与上下文工程.md` §2-§4；
  `agent_platform/memory/service.py`、`core/checkpoint.py`。
- **写**：给第 4 周的 mini agent 加三件：滑动窗口裁剪、SQLite 保存会话、
  按 user_id 的向量记忆；再加一个跨用户隔离测试。
- **验收**：重启进程后能接着聊；u1 的记忆 u2 召回为空；长对话 token 不再线性增长。
- **一句话**：我分得清三种记忆各存哪、什么时候删，不会把所有东西都塞进 messages。

## 4. 第二阶段（7-11 周）：吃透本项目

### 第 7 周：LangGraph 与 checkpoint

- **目标**：会画 StateGraph、用 checkpointer、用 `interrupt()` 做 HITL。
- **读**：`docs/learning/13-LangChain与LangGraph.md` §4.5、§5；
  `docs/adr/0003-hitl-with-langgraph-interrupt.md`、`docs/adr/0005-checkpoint-backends.md`；
  `core/workflow.py`。
- **写**：复现工单审批图：分类 → 敏感则 `interrupt()` → resume 后执行工具；
  用 SQLite saver 验证重启后还能恢复。
- **验收**：`POST /v1/tickets` 返回 `interrupted`；杀掉进程重启后 `resume` 仍成功；
  `tests/test_checkpoint.py` 全绿。
- **一句话**：我用 checkpoint 做过重启续跑和 HITL，不是只画过一张流程图。

### 第 8 周：MCP 与网关治理

- **目标**：理解 MCP 的 server/tool 模型，理解网关为什么要收口所有工具调用。
- **读**：`docs/adr/0001-langgraph-and-mcp-gateway.md`；`gateway/gateway.py`、
  `policy.py`、`audit.py`、`security.py`；MCP 规范 2026-07-28 的 tools 部分。
- **写**：加一个 MCP 工具（如 `get_weather`），注册进网关；写三条测试：
  无 token 401、角色不够 403、路径穿越 400。
- **验收**：越权请求返回 403 且审计里有 `denied` 事件；工具列表接口不泄露未授权工具。
- **一句话**：我把工具调用收口到网关，默认拒绝、全程审计，路径穿越在入参层就拦掉。

### 第 9 周：项目里的 RAG 与长期记忆

- **目标**：读懂知识库与记忆如何共用向量存储、如何按 metadata 分域。
- **读**：`docs/learning/16-记忆与上下文工程.md` §2.3、§3.6、§4；
  `knowledge/tools.py`、`memory/service.py`、`knowledge/store.py`。
- **写**：给记忆加一个 `delete(user_id, memory_id)` 方法 + API；写跨用户删除测试；
  用 `EXPLAIN` 看 `metadata @> ...` 是否走 GIN 索引。
- **验收**：u1 删除自己的记忆后召回为空，u2 的记忆不受影响；删除接口不能删别人的 id。
- **一句话**：我的长期记忆按 user_id 在存储层分域，并且有跨用户隔离和删除测试。

### 第 10 周：限流、预算、缓存、韧性

- **目标**：理解治理四件套的取舍，能证明限流和预算真的生效。
- **读**：`docs/learning/18-生产化与部署治理.md` §1、§3.2；
  `docs/adr/0006-runtime-backends-and-degradation.md`；`ratelimit.py`、`budget.py`、
  `cache.py`、`resilience.py`。
- **写**：用真实 Redis 跑滑动窗口压测（100 次并发，limit=20）；把 Redis 停掉，
  验证降级到本地桶；把预算调到 0.001 元，验证 402。
- **验收**：并发下通过数不超过 limit；Redis 挂掉服务不 500；超预算返回 402 而不是继续烧。
- **一句话**：我用 Redis Lua 做跨副本限流，Redis 挂了降级到本地桶，而不是放行。

### 第 11 周：评测与可观测

- **目标**：会写 golden、跑 pass@k/pass^k、看 trace 定位慢请求。
- **读**：`docs/learning/17-评测与可观测.md` §1-§5；
  `evaluation/harness.py`、`observability/metrics.py`、`tracing.py`、`middleware.py`。
- **写**：给 tracing 补 `gen_ai.operation.name="chat"`；跑
  `uv run python scripts/eval.py --threshold 80 --trials 3`；把一条 trace 导到 Langfuse。
- **验收**：报告里有 pass@3 与 pass^3；trace 里能看到模型名、input/output token、
  首 token 延迟；`/metrics` 能抓到 `agent_llm_cost_yuan_total`。
- **一句话**：我用 OTel 的 gen_ai 字段和 Prometheus 指标，把一次 Agent 请求拆成可检索的 trace。

## 7. 如果只有 8 周怎么砍

把 16 周压成 8 周，每周仍然 10 小时，总投入 80 小时。原则：**保主线、砍枝节、保可运行**。

| 周 | 合并内容 | 必须产出 |
|---|---|---|
| 1 | 第 1-3 周：Python + LLM + Prompt | 带配置/测试的 CLI + 成本估算器 |
| 2 | 第 4 周：手写 Agent 循环 | 3 工具、max_steps 的 mini agent |
| 3 | 第 5-6 周：RAG + 记忆 | ingest/search CLI + 跨用户隔离测试 |
| 4 | 第 7 周：LangGraph + checkpoint | 重启续跑的工单图 |
| 5 | 第 8 周：MCP + 网关 | 加一个工具 + 401/403/审计测试 |
| 6 | 第 10-11 周：治理 + 评测/可观测 | 429/402 证据 + pass@3/pass^3 报告 |
| 7 | 第 12-13 周：Docker + CI | 容器可跑 + 评测能红 |
| 8 | 第 15-16 周：简历 + 模拟面试 | 3 条 bullet + 5 分钟 demo |

砍掉的内容（明确不学，别焦虑）：

- A2A、多 Agent 协作、Agent 间通信；
- 前端 Console、复杂 UI；
- 多供应商模型路由的完整实现（只保留设计说明）；
- 50 条 golden 的全量维护（8 周版用 15 条）；
- K8s 真实集群（只画 Deployment 草案，讲清探针语义）；
- 全量压测（只做 50 并发 SSE 的一次基线）。

不能砍的底线：**可运行 demo、checkpoint 恢复、网关鉴权/限流、RAG+记忆分域、评测退出码、
Docker 镜像、3 条简历 bullet**。这七样是「项目能讲」的最小闭环。

## 9. 简历上怎么写这个项目

三条 bullet，动词开头、带数字、可被追问。数字都来自项目事实，别写没测过的 P95。

**1. 设计并实现企业级 Agent 平台（FastAPI + LangGraph + MCP），以 ReAct 编排 6 个工具、
HITL 工单双图，所有工具调用统一经网关做鉴权/限流/审计，覆盖 401/403/429/402 四类失败路径。**

可被追问：为什么用单 Agent 而不是多 Agent？网关四件套的顺序为什么是限流→权限→存在性→执行？
6 个工具分别是什么？HITL 的 `interrupt()` 恢复时怎么保证不重复执行？

**2. 重构 LangGraph 会话状态为 memory/SQLite/PostgreSQL 三档可插拔后端，实现写穿与按线程
惰性加载；用 25 个测试文件、146 个测试函数覆盖重启恢复、线程隔离与删除幂等。**

可被追问：为什么要三档而不是直接上 PG？写穿和重写协议的区别？SQLite 为什么不能多副本？
`thread_id` 的设计有没有问题（一个用户一段会话）？

**3. 搭建 golden dataset + LLM-as-judge 评测闭环，输出 pass@3/pass^3 双指标并接入 CI 退出码；
用 OTel `gen_ai.*` 与 Prometheus 指标定位模型调用成本与首 token 延迟。**

可被追问：pass@k 和 pass^k 差在哪，0.9^5 是多少？judge 的偏差怎么缓解？为什么 CI 只在
push 跑、PR 不跑？`gen_ai.*` 为什么不能当 Stable API？

每条 bullet 的准备方式：先写「我做了什么」，再补「用什么做的」，最后留一个「数字/取舍」。
面试官顺着任何一条追问三层，你都能指到文件、测试或 ADR，这条 bullet 就立住了。
