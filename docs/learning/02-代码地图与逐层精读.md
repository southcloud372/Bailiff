## 1. `context.py` —— 为什么需要 contextvars

**问题**：工具函数由 LangGraph 调用，签名是框架定的（`**kwargs`），塞不进 `principal`。
但工具执行又必须知道「谁在调」。

**做法**：把请求级状态放进 `ContextVar`。

```python
current_principal: ContextVar[Principal | None] = ContextVar("agent_principal", default=None)

@contextmanager
def principal_context(principal: Principal) -> Iterator[None]:
    token = current_principal.set(principal)
    try:
        yield
    finally:
        current_principal.reset(token)
```

**为什么不用全局变量**：FastAPI 并发处理请求，全局变量会串号。
`ContextVar` 随 asyncio task 自动隔离，且在 `async` 调用链里隐式传递。

**为什么不用 `threading.local`**：async 里一个线程跑多个任务，`local` 同样串号。

**易错点**：`reset(token)` 必须放 `finally`，否则异常路径会污染后续请求。
`tests/test_agent.py` 有对应用例。

## 2. `gateway/gateway.py` —— 治理四件套

这是整个项目最该讲清楚的一段，只有 80 行，但每个顺序都有理由。

```python
async def call(self, principal, tool, arguments):
    # 1. 限流（最早，防 DoS）
    if self._rate_limiter and not await self._rate_limiter.aallow(principal.id):
        self._record(..., "rate_limited", start); raise RateLimitExceeded

    # 2. 权限（先权限后存在性：不向未授权调用方泄露「工具是否存在」）
    if not self._policy.allows(principal, tool):
        self._record(..., "denied", start); raise PermissionDenied

    # 3. 存在性（已授权但未注册 = 配置错误）
    fn = self._registry.get(tool)
    if fn is None:
        self._record(..., "error", start); raise UnknownTool

    # 4. 执行（把身份传给工具，供按用户分域的工具使用）
    try:
        result = await fn(principal, arguments)
    except Exception:
        self._record(..., "error", start); raise

    self._record(..., "allowed", start)
    return result
```

四个设计点，每个都能单独被追问：

1. **为什么限流在权限前**：无权限请求也消耗资源，先挡洪水。
2. **为什么权限在存在性前**：否则攻击者可以通过 404/403 的差异枚举工具清单。
3. **为什么审计覆盖失败路径**：审计的价值在「谁试图做了什么」，失败的尝试同样重要。
4. **为什么工具签名是 `(principal, args)`**：让「按用户分域」的工具（记忆、文件）能拿到身份，
   而不是靠 contextvar 兜底——网关层显式传，减少隐式依赖。

对应测试：`tests/test_gateway.py`（含顺序验证：未授权调用不存在的工具，返回 403 而非 404）。

## 3. `gateway/mcp_client.py` —— 什么才算「真网关」

这个文件的 docstring 本身就是一个面试答案：

> 很多「MCP 网关」项目其实是「给几个 Python 函数套了个权限装饰器」——面试官问一句
> 「你的网关怎么发现工具、怎么连一个第三方 MCP server」就穿了。

真正的网关做五件事：

| 能力 | 代码位置 | 意义 |
|---|---|---|
| 作为 **MCP 客户端**连接 | `MCPClient.start()` → `Client(target)` | 支持 stdio 子进程 与 Streamable HTTP |
| **动态发现**工具 | `await client.list_tools()` | 不硬编码工具清单，schema 来自 server |
| 转成统一签名 | `_make_tool_fn(client, descriptor)` | 复用网关的鉴权/限流/审计 |
| **命名空间** | `_qualify()` → `server__tool` | 避免多 server 工具重名 |
| **故障隔离** | `start()` 内 try/except，`asyncio.gather` | 单 server 挂掉不影响其他 |

自动权限：`register_into()` 会给发现的工具追加一条 `PermissionRule`，
因为策略是**默认拒绝**的——不自动放行，连上也没用。

**面试追问预案**：
- 「多个 server 有同名工具怎么办？」→ 前缀命名空间。
- 「server 挂了会怎样？」→ 连接失败只记录 `last_error`，health 里可见，其他 server 照常。
- 「工具 schema 怎么给模型？」→ `input_schema` 原样转成 OpenAI function-calling 格式
  （`mcp_tools_as_langchain` 预留了这个转换）。

## 4. `core/agent.py` —— 自主 Agent 的组装

三段式，每段都能单独讲：

### 4.1 `build_model`：模型 + 回调

```python
callbacks = [TracingCallback()]
if cost_tracker is not None:
    callbacks.append(CostCallbackHandler(cost_tracker))
return ChatOpenAI(model=settings.model, ..., callbacks=callbacks)
```

回调是「横切能力不侵入业务」的典型手法：计费和 trace 都不需要改 Agent 逻辑。

### 4.2 `build_tools`：把网关包成 LangChain 工具

```python
async def _run(**kwargs):
    principal = current_principal.get()
    if principal is None:
        raise RuntimeError("工具执行时未设置 principal（需经 Agent.chat 进入）")
    span = start_tool_span(name, principal.id)
    try:
        return await gateway.call(principal, name, dict(kwargs))
    finally:
        span.end()
```

注意 `finally: span.end()`——span 必须成对关闭，否则 trace 里全是未完成 span。

### 4.3 `Agent.chat / ask / stream`

- `chat`：有状态，多轮，走 checkpoint
- `ask`：无状态，独立 thread，用完 `_drop_thread` 清理，可开语义缓存
- `stream`：`stream_mode="messages"`，只 yield `AIMessage/AIMessageChunk` 的文本分块，
  跳过工具调用分块（content 为空）

**为什么 `ask` 要删 thread**：否则一问一答会把 checkpoint 表撑爆。这是无状态接口最容易漏的运维债。

## 5. `core/workflow.py` —— HITL 的真正实现

关键只有三行：

```python
async def approval_node(state):
    decision = interrupt({           # 暂停图，把审批上下文抛给调用方
        "type": "approval",
        "request": state["request"],
        "action": state["tool_name"],
        "arguments": state["tool_args"],
    })
    return {"approval": decision}    # 恢复时这里拿到 Command(resume=...) 的值
```

配合路由：

```python
def route(state): return "approval" if state["intent"] == "sensitive" else "execute"
def route_after_approval(state):
    return "execute" if state.get("approval", {}).get("approve") else "answer"
```

**`interrupt()` 的机制**：它不是 `await` 一个外部事件，而是**抛出图执行的暂停信号**，
把当前状态写进 checkpoint，然后返回给调用方。恢复时用 `Command(resume=value)` 重新进入，
`interrupt()` 那一行会「返回」resume 的值，继续往下走。

**这就是为什么必须持久化 checkpoint**：暂停期间进程可能重启。
用 `MemorySaver` 的话，人第二天点「同意」时，图状态已经不存在了。

对应测试：`tests/test_workflow.py` 的 interrupt/resume 用例（注入假 classify/answer，不花 token）。

## 6. `core/checkpoint.py` —— 三级后端

| 后端 | 类 | 场景 |
|---|---|---|
| memory | `InMemorySaver` | 单测/CI |
| sqlite | `SqliteCheckpointSaver`（自研，写穿） | 本地/单机 |
| postgres | `AsyncPostgresSaver` + 连接池 | 生产多副本 |

`SqliteCheckpointSaver` 的巧妙处：**继承官方 `InMemorySaver` 而不是自己实现协议**。
原因写在 docstring 里——LangGraph 的 checkpoint 有「增量 channel」语义，自己实现极易写错。
它只在 `put/put_writes/delete_thread` 后把变化写盘，读时按 `thread_id` 惰性 hydrate。

**面试可讲**：「我没有重写协议，我做的是内存一级缓存 + SQLite 持久层的写穿。
好处是完全复用官方对 delta channel 的计算，坏处是内存会随活跃线程增长——所以无状态接口用完即删。」

## 7. `router/` —— 成本与稳定性

### 7.1 `cost.py`：成本必须实时可见

`CostCallbackHandler` 挂在模型上，从 `LLMResult.llm_output` 里取 token 用量，
用 `litellm.cost_per_token` 算钱（**不自建价格表**——供应商一年调价两次，自建必过期）。

`CostTracker.summary()` 返回：
```
total_cost / total_prompt_tokens / total_completion_tokens
/ total_cached_tokens / cache_hit_rate / by_model{...}
```

`cache_hit_rate` 是 DeepSeek 上下文缓存命中率，直接对应省钱比例——这是一个很能打的指标。

### 7.2 `budget.py`：硬限额

`BudgetPolicy.check(tracker)` 在每次模型调用前执行，超限抛 `BudgetExceeded` → API 返回 402。
注意 402（Payment Required）而不是 429：语义是「配额用尽」，不是「太快」。

### 7.3 `resilience.py`：重试 + 熔断

- `RetryPolicy.delay_for`：指数退避 + 抖动（避免同频重试打成脉冲）
- `CircuitBreaker`：连续失败达阈值后打开，快速失败，冷却后半开试探

**为什么重试要加抖动**：所有客户端同时失败、同时重试，会在恢复瞬间把上游再打挂（重试风暴）。

### 7.4 `cache.py`：语义缓存

按 embedding 余弦相似度命中，阈值默认 0.95。

**必须能讲清的两个点**：
1. 为什么不是精确字符串缓存——真实用户不会重复一模一样的措辞。
2. 阈值怎么定——不是拍 0.95，应该在 golden dataset 上扫「命中率 × 正确率」曲线选点。

## 8. `knowledge/` —— RAG 的工程细节

| 文件 | 关键点 |
|---|---|
| `chunking.py` | 按段落/长度切分，带 source 元数据（引用溯源的基础） |
| `embedder.py` | Ollama OpenAI 兼容端点；`FakeEmbedder` 用字符 3-gram 哈希，确定性、可离线测试 |
| `store.py` | `InMemoryVectorStore`（测试）+ `PgVectorStore`（生产） |
| `retriever.py` | 检索 + 过滤（`metadata @> {...}` 分域） |
| `rag.py` | 管道 + `format_context` 带 `[来源: xxx]` |

`PgVectorStore` 有三个容易踩的坑，代码里都处理了：

1. **连接池**：`psycopg.AsyncConnection` 不是并发安全的，共享单连接会报
   `another command is already in progress`。
2. **HNSW 索引**：不建索引就是全表扫 + 逐行算距离，几万条片段直接秒级。
   `USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64)`。
3. **维度必须声明**：`vector(1024)`，pgvector 不给无维度列建 ANN 索引。

## 9. `evaluation/` —— 为什么要 pass^k

`harness.py` 里两个指标：

- `pass@k`：k 次里**至少一次**成功 → 能力上限
- `pass^k`：k 次**全部**成功 → 部署可靠性

配套的数学事实：单步 90% × 5 步 ≈ 59%，10 步 ≈ 35%。
所以「demo 能跑、上线就废」不是玄学，是乘法。

`judge.py` 用结构化输出让另一个模型打分（0-100 + 理由），
**judge 必须是独立实例**，避免「自己给自己打分」的偏向。

## 10. `observability/` —— 零依赖的 Prometheus

`metrics.py` 自己实现了 Counter/Gauge/Histogram 和文本暴露格式，不用 `prometheus-client`。
理由写在文件头：演示环境依赖越少越不容易起不来；文本格式是稳定公开规范，几十行够了。

`health.py` 是这次改造新增的：
- 探针并发执行（`asyncio.gather`）
- 每个探针自己吞异常，永不让 `/readyz` 崩
- `critical=False` 的探针只报告不阻断（比如缓存挂了应该降级直连模型）

`middleware.py` 是**纯 ASGI** 而不是 `BaseHTTPMiddleware`：
后者会为每个请求包一层 anyio task，SSE 容易出现首包延迟或缓冲异常。

## 11. `scripts/serve.py` —— 组合根

这里是「所有东西在哪里被接起来」的地方，也是面试时最能体现工程感的一段：

```python
runtime = RuntimeSettings()          # 决定本地还是生产
agent_saver = _make_saver("agent")   # 单文件单图，避免 thread 撞车
ticket_saver = _make_saver("tickets")
limiter = build_rate_limiter(...)
cache = SemanticCache(...) if runtime.cache_enabled else None
agent = build_agent(..., checkpointer=agent_saver, cache=cache)
workflow = build_ticket_workflow(..., checkpointer=ticket_saver)
app = create_app(..., startup_hooks=[_setup_postgres_guarded, _start_mcp],
                 shutdown_hooks=[_stop_mcp])
```

**为什么用 startup/shutdown hooks 而不是在模块顶层做**：
Postgres 建表是异步的，MCP 连接需要事件循环，都必须等 FastAPI lifespan 启动后执行。
写在模块顶层会在 import 时阻塞，甚至因为「没有运行中的事件循环」直接报错。

## 面试追问

**Q：你这个网关和直接在 Agent 里挂几个 `@tool` 有什么区别？**
A：三个差异。一是治理不旁路——工具只能通过 `Gateway.call` 执行，限流/权限/审计强制生效；
二是工具可以来自外部进程（MCP server），不是同进程函数；三是权限默认拒绝，
新接一个 server 必须显式放行。直接挂函数的话，任何一个 `@tool` 都绕过了全部治理。

**Q：为什么工具函数签名要带 principal？**
A：因为「按用户分域」的工具（长期记忆、文件）必须知道调用者是谁。
放参数里比放 contextvar 更显式，减少隐式依赖；contextvar 只用于框架无法传参的边界
（LangGraph 调工具时）。

**Q：你的 sqlite checkpoint 会不会成为瓶颈？**
A：会，所以它只定位单机。写穿是同步 SQLite 写 + WAL，单机几十 QPS 没问题；
多副本必须切 Postgres。这是刻意的分层，不是「没做完」——`/readyz` 会显示当前后端。
